# IEDSyncTogether v0.3.2 IED diagnostics

v0.3.2 removes the v0.3.1 `AddActorBlock` experiment and returns to the validated public IED Custom Item renderer.

No private IED runtime hook is installed. No IED setting is modified by IEDSyncTogether.

## Why this build exists

The v0.3.1 dual-client test established that `IED.AddActorBlock` is too broad for IEDSyncTogether: it suppresses the ordinary IED gear layer but also prevents IED Custom Items from being rendered. Only equipment genuinely equipped through Skyrim Together remains visible.

IED's official source shows a more useful native path inside `DoObjectEvaluation`:

```text
if disable_npc_slots is false OR holder.IsPlayer()
    ProcessSlots

ProcessCustom
```

Therefore `disable_npc_slots=true` should skip ordinary equipment slots for NPCs while still processing Custom Items. IED classifies an `ActorObjectHolder` as the player by exact `Actor* == PlayerCharacter*` pointer comparison.

v0.3.2 verifies the two assumptions needed for that native path.

## Read-only diagnostics

At `DataLoaded`, IEDSyncTogether reads the same settings file used by IED:

```text
Data\SKSE\Plugins\IED\Settings.json
```

and logs the boolean value of:

```json
"disable_npc_slots"
```

This file is opened read-only. IEDSyncTogether never writes or changes it.

When a remote STR proxy resolves, v0.3.2 logs its FormID and compares its actual `Actor*` pointer to the local `PlayerCharacter*` pointer. The comparison result is what matters because that mirrors IED's own `kIsPlayer` initialization rule.

## Expected log lines

Startup:

```text
IEDSyncTogether v0.3.2 loading
IED integration mode: official Papyrus Custom Item API + read-only diagnostics; no ActorBlock probe and no IED runtime patch installed
IED settings diagnostic: path="...\Data\SKSE\Plugins\IED\Settings.json" disable_npc_slots=true source=IED Settings.json (read-only)
IED v0.3.2 diagnostics started: read-only IED settings + STR proxy PlayerCharacter classification
```

For each proxy:

```text
IED proxy classification diagnostic: proxy=FFxxxxxx player=00000014 proxyIsPlayerPointer=0 proxyIsPlayerFormID=0
```

`proxyIsPlayerPointer=0` is the important result.

## Test protocol

Install the same v0.3.2 archive on both clients. In IED on both PCs, enable `Disable NPC equipment displays`, then start Skyrim Together as usual.

Use the same equipment pattern as the v0.3.1 test:

- keep one or more weapons/shields favorited but stowed;
- keep at least one different item genuinely equipped;
- verify the local owner still sees the normal IED favorites;
- compare what the remote client sees on the STR proxy.

Send both `IEDSyncTogether.log` files after the test. The IED logs are useful too if the visible result remains inconsistent.

## Interpretation

### `disable_npc_slots=false`

The IED setting is not persisted in the settings file IED loads. Fix that first; there is no reason to investigate proxy classification yet.

### `disable_npc_slots=true` and `proxyIsPlayerPointer=1`

The STR proxy is somehow being represented by the local PlayerCharacter pointer. That would explain why IED still runs `ProcessSlots` despite NPC slot suppression.

### `disable_npc_slots=true` and `proxyIsPlayerPointer=0`

This is the expected IED classification. If ordinary inventory-derived gear is still visible, that visible layer is not explained by IED's normal `ProcessSlots` branch and must be isolated separately (STR equipment representation, another IED path, or another mod).

If only equipped STR items plus IEDSyncTogether favorites are visible, the native IED setting is sufficient and no suppression hook is needed.

## Upgrade note from v0.3.1

The active ActorBlock probe is gone. The existing proxy registration path already calls `IED.RemoveActorBlock` before rebuilding IEDSyncTogether Custom Items, so a block left by the v0.3.1 experiment is cleared once the proxy is registered again.
